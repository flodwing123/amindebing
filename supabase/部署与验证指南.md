# 「啊敏的兵」正式部署与验证指南

> 架构：**GitHub Pages 长期托管（静态前端）+ Supabase（邮箱登录 + 多设备数据同步）**
> 硬性约束已满足：无框架无构建（源码即产物）· 原生 fetch 自写客户端（无官方 SDK）· 全表 RLS（auth.uid() = user_id）· 登出清缓存重绘（账号隔离）

## 一、需要你完成的 2 件事（其余我来做）

### ① 在 Supabase 执行建表 SQL（约 1 分钟）

1. 登录 Supabase 控制台 → 进入你的项目
2. 左侧 **SQL Editor** → **New query**
3. 把 `supabase/schema.sql` 的全部内容粘贴进去 → **Run**
4. 应看到绿色 "Success. No rows returned" 提示

### ② 把以下 4 项信息发给我（部署用，用完即弃）

| 信息 | 从哪里获取 | 示例 |
|------|-----------|------|
| GitHub 用户名 | GitHub 首页 | `zhangsan` |
| 仓库名 | 已创建的 Public 仓库名 | `amindebing` |
| GitHub PAT | Settings → Developer settings → Tokens(classic)，勾 `repo`，有效期 7 天 | `ghp_xxx` |
| Supabase Project URL | Settings → General → Project URL | `https://abcd.supabase.co` |
| Supabase Publishable Key | Settings → API → Publishable Key（`sb_publishable_...`，旧版叫 anon key；**不要**给 service_role/secret key） | `sb_publishable_xxx` |

我收到后会自动：
- 把 Project URL + Publishable Key 写入 `js/sb-config.js`
- 用 API 把全部文件推送到你的公开仓库 main 分支
- 调用 GitHub API 开启 Pages（main 分支根目录）
- 返回长期访问网址

## 二、部署步骤（我执行，你旁观）

1. 校验 `js/sb-config.js` 配置已填入真实值
2. 通过 GitHub REST API 逐文件上传（Contents API，Base64 编码，main 分支）
3. `POST /repos/{owner}/{repo}/pages` 开启 Pages
4. 等待 1~3 分钟构建完成
5. 验证线上：首页 200、sw.js 版本、全部资源可达

## 三、端到端验证清单（部署后逐项勾选）

**账号**
- [ ] 首次打开显示登录页（未登录不显示任何工作台数据）
- [ ] 注册新账号成功（无需邮箱验证，注册即登录）
- [ ] 登录成功进入工作台，侧边栏显示邮箱
- [ ] 刷新页面仍保持登录态（token 持久化，过期自动 refresh）

**数据**
- [ ] 新建一条数据（如学生花名册）→ 数据自动同步到云端
- [ ] 修改一条数据 → 云端更新
- [ ] 删除一条数据 → 云端对应行被删除（差集删除）
- [ ] 换一台设备登录同一账号 → 数据完整可见

**账号隔离**
- [ ] 退出登录 → 本地缓存全部清除，页面重绘回登录页
- [ ] 换一个账号登录 → 看不到上一个账号的任何数据

**健壮性**
- [ ] 断网操作 → 数据不丢（先本地后云端，联网后自动补推）
- [ ] 控制台（F12）零报错

## 四、以后修改工作台后如何更新线上版本

- **方式 A（推荐，找 AI）**：改完本地代码后，让我用同一个 PAT 重新推送变更文件即可（也可直接提交 GitHub 网页编辑）。
- **方式 B（自助）**：在 GitHub 仓库页面逐个编辑文件 → Commit → Pages 自动重新构建，1~2 分钟后线上更新。
- 每次改动记得**递增 sw.js 缓存版本号**（如 `amindebing-v9` → `v9.1`），避免手机端缓存残留。

## 五、数据说明（务必区分）

| 状态 | 数据在哪里 |
|------|-----------|
| **未登录 / 未配置同步** | 仅浏览器 localStorage（本机） |
| **登录后（Supabase）** | localStorage 保留一份（离线兜底）+ 自动同步到 Supabase 云端数据库（多设备互通） |
| **退出登录** | 本地缓存清除；云端数据保留，下次登录自动拉回 |

> 结论：**网页长期可访问（GitHub Pages）** 与 **数据云端同步（Supabase）** 是两件事。网页部署后任何人打开网址都可用，但只有登录了你的账号才能看到你的数据；数据真正上云发生在你登录并使用同步功能之后。

## 八、RLS 修复记录（2026-08-18）

- **症状**：注册成功，但写入数据时返回 `403 new row violates row-level security policy for table "user_sync"`（SELECT/DELETE 正常）
- **原因**：`user_sync` 表的 INSERT / UPDATE 策略未生效（首次建表时策略可能未完整应用）
- **修复**：用户在执行 `supabase/fix-rls.sql`（drop + create 重建 4 个策略，幂等可重复执行）后解决
- **验证**：`node supabase/e2e-verify.cjs` 自动跑完 9 项检查，**9/9 全部通过**：
  1. 注册即登录，拿到 user.id ✔

  5. delete 生效（delete 策略 / 差集删除）✔
